紐約中央公園　使用說明
================================

【這是什麼】
紐約曼哈頓中央公園與四周街區的 1:2 實景還原。不是憑印象蓋的：街道、建築輪廓、樓高、湖泊與水庫、
公園步道、球場草坪、岩盤、林地、每一棵有登錄的樹、長椅與路燈，全部依 OpenStreetMap 真實資料
（透過 Overture Maps 2026-10-21 發行版取得）換算成方塊座標後生成。可用建築放置台放置。

【比例與範圍】
・比例 1:2（1 格 = 2 公尺），水平與高度同比例。中央公園實長約 4.1 km × 0.84 km → 2050 × 420 格。
・範圍：南到 56 街、北到 112 街，東到公園大道（含）、西到哥倫布大道（含）。
・全區 寬 768（X）× 深 2304（Z），高度依各分件最高建築而定（最高 253 格，中央公園大樓 472 m → 236 格）。
  共 432 分件（12 × 36，每件 64×64）。
・方位：地圖已依曼哈頓街網「轉正」，大道和 Z 軸平行，街道和 X 軸平行（與真北差 29°，就是紐約人說的「曼哈頓北」）。
  -Z = 上城（110 街、哈林湖），+Z = 下城（57 街、億萬富翁街），+X = 東（第五大道、上東區），-X = 西（中央公園西、上西區）。
・高度：結構 y=0～5 是地層，街道與人行道地面在 y=6；湖面在 y=5；公園內草地依地形高 0～5 格、岩盤露頭再高 1～7 格。

【還原了什麼】
街道
・3889 棟建築依 OSM 輪廓與高度生成；有 building:part 的（雙塔、退縮、尖塔）照各部件高度分段。
・所有大道與街道依道路等級給寬度；雙向道畫黃色雙中線；路口斑馬線照 OSM 的行人穿越道位置。
・人行道（淺灰水泥、石質路緣）、公園邊的六角磚人行道、公園外圍矮石牆（入口處斷開）。
・路燈、長椅、消防栓、紅綠燈照 OSM 點位放置；行道樹照 NYC 行道樹點位。
・公園大道 97 街以北的地鐵北方鐵路石砌高架路堤（含鐵軌，路口處架空）。
建築外觀
・依位置、用途、高度與 OSM 外牆資料分成褐石屋、紅磚、米色磚、石灰岩、白磚、玻璃帷幕等風格；
  每 3 格一層（約 2 個實際樓層）、窗格、腰線、女兒牆、矮樓的石簷口、上東／上西區屋頂的木製水塔。
・大道（麥迪遜、哥倫布、第六／第七大道）、59 街以南、110 街以北的一樓是玻璃店面與招牌帶。
・特製：432 公園大道（白色方格窗）、斯坦威大樓（陶板＋銅色鰭片）、通用汽車大樓（白色直條）、
  廣場飯店／皮埃爾飯店／雪梨荷蘭飯店（銅綠屋頂）、達科塔公寓（石板屋頂）、自然史博物館（花崗岩）、
  大都會博物館（石灰岩）、古根漢（白色水平帶）、蘋果第五大道玻璃方塊、貝爾維德雷城堡（城垛）。
・室內：空樓層＋樓板，每 16 格一道隔間牆（留門洞），每棟一樓至少一扇面向人行道的門，
  室內放了隱形光源方塊（light_block），避免怪物生成。
中央公園
・賈桂琳甘迺迪水庫（外圍鐵欄、跑道）、湖、龜池、哈林湖、池塘、模型船池、泳池、泉與溪（The Loch、The Gill）。
・弓橋（白色）與 100 多座跨水步道橋；65／79／86／97 街橫貫道路下沉 4 格、兩側石牆，公園車道與步道以石橋跨過。
・羊草原、大草坪、北草地、各球場（紅土內野、白線）、網球場、遊戲場、花園花床、動物園、畢士達平台（地磚圖樣）與噴泉天使像、
  林蔭大道、漫步區（Ramble）與北林的密林、曼哈頓片岩露頭、約 50 座雕像（石座＋青銅）。
・7379 棵樹：OSM 有登錄的樹照點位與樹種（松、銀杏／皂莢、櫻、橡）種植，林地再依密度補植。

【與真實的差異（簡化之處）】
・城市地面統一為平地（實際曼哈頓有 10～40 m 起伏）；公園地形依資料特徵（林地、岩盤、草坪）推估，不是測量高程。
・公園內車道與步道的立體交叉拱橋（如 Glen Span Arch）以平面路口表示，只標出橋面石材。
・沒有 OSM 資料的物件不另外捏造：沃爾曼溜冰場、玫瑰中心球體等不在資料內，未特製。
・建築外牆材質多為依規則推定（OSM 只有少數建築登錄外牆材質與顏色）。

【匯入與啟用】
1. 雙擊「紐約中央公園.mcpack」匯入 Minecraft 基岩版。
2. 建立或編輯世界 → 行為包 → 啟用「紐約中央公園」，並開啟作弊（允許指令）。建議用「超平坦」世界。
3. 準備 768 × 2304 的空地。座標 = 場地西北角（最小 X/Y/Z）。超平坦世界原點 Y 用 -64
   （地面會比周圍草地高 3 格，像一塊微微墊高的城市台地）。

【一鍵放置（建議）】
以原點 (0, -64, 0) 為例，依序執行（每次的座標都要一樣）：
  /execute positioned 0 -64 0 run function cpnyc/prepare
  （等 3～5 秒讓區塊載入）
  /execute positioned 0 -64 0 run function cpnyc/build1
  （等 3～5 秒）
  /execute positioned 0 -64 0 run function cpnyc/build2
  ……依此類推到 build18（每段放 2 列共 24 個分件，聊天欄會顯示「第 N/18 段完成」）
  /function cpnyc/cleanup
每一段會建立 6 個常駐區塊（tickingarea，每個 128×128）；世界上限 10 個，請先確認你的世界沒有超過 4 個其他常駐區塊。
若某一塊沒出現，通常是區塊尚未載入：走近那一區，再用同樣座標執行一次該段 build（重複載入不會壞）。
build1 是最北邊（112 街），build18 是最南邊（57 街）。

【逐件放置（結構方塊或指令）】
取得結構方塊：/give @s structure_block → 放下 → 模式切「載入」→ 輸入結構名稱（旋轉 0°、無鏡像、完整性 100%）。
  分件 cpnyc_261118:tile_x<i>_z<j> 放在 (X+64i, Y, Z+64j)，i = 0～11、j = 0～35。
    例：/structure load cpnyc_261118:tile_x0_z0 0 -64 0
        /structure load cpnyc_261118:tile_x6_z25 384 -64 1600
完整載入順序寫在行為包的 functions/cpnyc/build1～build18.mcfunction 裡。

【注意】
  ・結構裡的空氣會清掉原地的方塊，請放在空地上。
  ・只需匯入行為包，不需更換 db 或世界檔。這不是 Java 版 schematic，也不是完整世界。
  ・各分件高度不同（公園約 25 格，摩天大樓區最高 253 格），都從同一個 Y 載入，地面會自動對齊。
